# Ask Capacity (Sadie) - Chat API Contract

This document defines the proposed request/response format for integrating the Sadie chatbot frontend with the backend LLM and retrieval services.

## Base Endpoint
`POST /api/v1/chat`

## Request Payload

When the user sends a message in the chat interface, the frontend will dispatch the following JSON payload:

```json
{
  "conversationId": "conv-12345",
  "message": "What is the best way to close my A/B Testing skill gap?",
  "context": {
    "page": "learning",
    "selectedCompetency": "A/B Testing",
    "userRole": "trainee",
    "userId": 1
  }
}
```

### Request Fields
- `conversationId` (string | null): Unique identifier for the conversation. If `null`, the backend should create a new conversation and return the new ID.
- `message` (string): The latest text message sent by the user.
- `context` (object):
  - `page` (enum): The current page context where the user opened the chat. Allowed values: `overview`, `assessment`, `readiness`, `learning`, `courses`, `mentor`, `passport`, `knowledge`, `certificates`, `teams`, `opportunities`, `community`, `profile`.
  - `selectedCompetency` (string, optional): A currently active or focused competency.
  - `userRole` (enum): `trainee`, `trainer`, or `admin`.
  - `userId` (number): The ID of the currently authenticated user for contextualizing the query against their profile.

## Response Payload

The backend should process the query, retrieve relevant organizational data, call the LLM securely, and return the following JSON structure:

```json
{
  "conversationId": "conv-12345",
  "message": {
    "id": "msg-9876",
    "role": "assistant",
    "content": "I suggest starting with the 'Advanced Experimentation Workshop'...",
    "createdAt": "2026-09-17T10:00:00Z",
    "sources": [
      {
        "title": "Advanced Experimentation Workshop",
        "url": "/courses/adv-exp",
        "type": "course"
      }
    ]
  }
}
```

### Response Fields
- `conversationId` (string): The ID of the conversation (especially important if it was newly created).
- `message` (object): 
  - `id` (string): Unique identifier for the assistant's message.
  - `role` (string): Always `"assistant"`.
  - `content` (string): The markdown-formatted text response generated by the LLM.
  - `createdAt` (string): ISO 8601 timestamp.
  - `sources` (array, optional): A list of grounded sources the LLM used to generate the answer.
    - `title` (string): The display title of the source.
    - `url` (string, optional): A link to the source if applicable.
    - `type` (enum): The type of source. Allowed values: `course`, `expert`, `document`, `role`.

## Implementation Notes for Backend
1. **Security**: The backend must ensure that the user only has access to their own `conversationId` records and that `userId` provided matches the authenticated token.
2. **LLM Calls**: The browser must *never* communicate with the LLM directly (e.g., OpenAI API) or hold API keys. The frontend solely communicates with this defined internal API endpoint.
3. **Retrieval**: The `sources` array is critical for the "Grounded Learning Assistant" promise. The backend should use RAG (Retrieval-Augmented Generation) against verified company knowledge and trainee data to populate these fields.
